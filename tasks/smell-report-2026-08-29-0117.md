# RedSQLite 全项目架构审查报告

**项目:** redsqlite（Wails v3 + Go + React 19/TS 的 SQLite 桌面客户端）
**范围:** 全项目 —— Go 后端（domain/internal/repository/services/main.go）+ 前端（frontend/src）+ 测试与工程卫生
**日期:** 2026-08-29
**分析器:** smell skill（Ducc）
**规模:** Go 53 文件 ≈ 11,500 行；TS/TSX 42 文件 ≈ 6,550 行

---

## 执行摘要

项目整体是**健康的分层模块单体**（组件 → api 封装 → bindings → services → repository → database/sql），文档化的 14 条架构不变量绝大多数被代码忠实执行，工程质量明显高于同类规模项目：SQL 注入防线（参数绑定 + 标识符白名单 + DDL 生成器集中）贯彻一致；零 TODO/FIXME、零注释掉的代码、零 console.log；`go vet` 干净、全部后端测试通过、`wails3 task build` 与 `tsc` 零错误（本次会话实测验证）。

本次审查发现 **2 个严重问题、16 个警告、18 条建议**。最需要处理的是：

1. **QueryPage 结果网格未过滤 null 行**（`QueryPage.tsx:357/364`）——`as CellValue[][]` 强转掩盖了 bindings 生成的 `(any[] | null)[] | null` 类型，一旦后端出现 null 行即触发 `row.map is not a function` 崩溃，直接违反不变量 10（TableDataPage 做了过滤，QueryPage 漏了）。
2. **前端零测试基础设施**——6,500 行 TS 无任何测试运行器（package.json 无 test 脚本），其中含 215 行 SQL 格式化器、633 行游标/偏移分页状态机等非平凡逻辑。
3. **`buildRedesign` 501 行巨型函数**与三处 500~930 行的上帝文件，是后续演进的最大摩擦点。
4. **跨包重复代码**：rowid 分块拷贝引擎在两个 repository 各写一份；前端 CreateTableModal/RedesignModal 有约 150 行逐字重复的外键编辑器。

架构风格本身没有方向性问题；问题集中在**局部体量失控**（长函数/大文件）、**复制粘贴扩散**与**测试空白**三类。

## 架构风格判定

**分层模块单体（Layered Modular Monolith）**，单进程桌面应用，五层职责清晰：

```
React 组件 → src/api（connId 首参封装）→ frontend/bindings（生成）
          → Go services（connID 首参）→ repository（按连接构造）→ database/sql → SQLite
```

### 风格期望 vs 实际

| 期望 | 实际 | 状态 |
|---|---|---|
| 组件禁止直连 bindings（不变量） | 全项目 grep 零命中，全部经 `src/api` | ✅ |
| 服务层不持有 `*sql.DB`（不变量 1） | export/import 服务经 `store.DB()` 取裸句柄传给 internal 引擎；其余服务全部经 repository | ⚠️ 有文档注释护栏的逃生舱 |
| 值参数绑定 / 标识符过白名单（不变量 3） | 数据路径全部 `?` 绑定，标识符全部 `ValidateAndQuote`；但"DDL 只出自 schemadsl"不成立——DROP/RENAME/CREATE INDEX 等手拼 DDL 散布在 4 个服务文件（均经 quote，注入安全成立，文档与代码不符） | ⚠️ |
| Tab 携带 connId、按连接过滤（不变量 9） | 完整执行；store 间依赖单向无环 | ✅ |
| 进度事件带连接 ID（不变量 14） | redesign 发 `connId`、transfer 发 `targetConnId`，两套键名；前端各自匹配所以能工作，但契约不统一 | ⚠️ |
| Emit 前判空 application.Get() | 两处 Emit 均有 nil 守卫，测试在无应用实例环境下跑通 Apply 路径佐证 | ✅ |
| bindings 可空类型前端收窄（不变量 10） | api 层与 TableDataPage 正确；**QueryPage 两处遗漏**（见严重 #1） | 🔴 |
| 主题颜色只走 CSS 变量（不变量 11） | 组件零硬编码色；global.css 内 1 处 rgba 字面量导致浅色主题徽章色不匹配 | ⚠️ |

## 详细发现（重点条目）

### 发现 #1：QueryPage 网格 null 行未收窄 🔴

- **类别:** 正确性 / 不变量违反　**反模式:** Ignored Nullability + 类型强转去检查
- **位置:** `frontend/src/pages/QueryPage.tsx:357, 364`
- **证据:** `rows={(batchGridItem.result.rows ?? []) as CellValue[][]}`；生成类型（`bindings/.../domain/models.ts:285`）为 `"rows": (any[] | null)[] | null`。`?? []` 只消外层 null，行元素可为 null；`as` 强转让编译器闭嘴；`DataGrid.tsx:209` 直接 `row.map(...)`。
- **违反:** 项目不变量 10（"行可能为 null，前端使用前必须过滤收窄"——TableDataPage.tsx:152-155 是正面示范）。
- **修复:** 抽共享 `narrowRows` 工具（或直接照抄 TableDataPage 的 filter），两处替换，删除 `as` 强转。

### 发现 #2：前端零测试基础设施 🔴

- **类别:** 测试　**反模式:** No Tests
- **位置:** `frontend/package.json`（scripts 仅 dev/build；devDependencies 无任何测试框架）；`frontend/src` 下零 `*.test.*` 文件。
- **影响面:** `utils/sqlFormat.ts`（215 行手写分词器）、`TableDataPage.tsx`（游标+OFFSET+异步计数+过期守卫状态机）、`tabsStore.ts`、`history.ts` 均无回归保护；AGENTS.md 路线图已承认此债。
- **修复:** 引入 vitest + @testing-library/react；第一批目标是纯逻辑（sqlFormat、keyOfRow/normalizeKeyValue、history）而非组件渲染。

### 发现 #3：buildRedesign 巨型函数 🟡

- **类别:** 内聚　**反模式:** Long Method（501 行，阈值 50）
- **位置:** `services/redesign.go:109-608`
- **证据:** 单函数承担：只读检查 → 7 次仓储调用收集现状 → 保守阻断规则 → 列映射校验 → PK/AUTOINCREMENT → 单/复合外键聚合 → 临时名碰撞循环 → CREATE 生成 → 拷贝计划 → 触发器先删后建 → 索引重建（含改名映射与唯一约束再生）→ 警告。`statements[2:]` 位置契约（:601）靠注释（:599-600）维持。
- **修复:** 无行为变更拆为 collectState / validateColumns / buildFKSpecs / rebuildIndexes / rebuildTriggers / buildWarnings；内部重复块（#26）顺带消除。

### 发现 #5：rowid 分块引擎跨包重复 🟡

- **类别:** 重复　**反模式:** Duplicated Code
- **位置:** `repository/schema_repository.go:583-640`（execRedesignCopy）vs `repository/transfer_repository.go:296-349`
- **证据:** 相同的边界探测循环（`SELECT rowid ... LIMIT 1 OFFSET %d` 探测 → `WHERE rowid > ? AND rowid <= ?` 分块拷贝）、相同中文注释（"边界探测…免 OFFSET"）。
- **修复:** 抽 `internal/chunkcopy` 或 repository 共享辅助（注意它是 #19 建议独立成包的重建引擎的一部分）。

### 发现 #11：Esc 关闭所有叠放弹窗 🟡

- **类别:** 正确性（UX 数据丢失）　**反模式:** Missing Modal Stack
- **位置:** `components/Modal.tsx:14-20`；叠放场景 `CreateTableModal.tsx:147+396`、`RedesignModal.tsx:218+397`、`DdlModal.tsx:50+67`、`CellView.tsx:27-32`
- **证据:** 每个 Modal 实例独立 `window.addEventListener("keydown", onKey)`，Esc 触发所有实例的 onClose。
- **修复:** 模块级打开计数栈，只有栈顶响应 Esc；或事件里比较时间戳/层号。

### 发现 #16：注释承诺的块大小钳制不存在 🟡

- **类别:** 文档失真 + 性能　**反模式:** Lying Comment + Dead Constant
- **位置:** `repository/schema_repository.go:486-490, 521`；`services/redesign.go:94-106`
- **证据:** `redesignChunkMax = 50000` 声明后唯一使用是 `chunkSize = redesignChunkMin`；服务侧 `size := total / 200` 无上界。注释两处都写"上限 50000"。
- **修复:** 要么实现钳制 `min(total/200, 50000)`，要么删常量改注释——二选一，别让注释骗人。

## 依赖图分析

- **Go 分层单向无环**：services → repository → database/sql；internal/* 被三层引用但互不依赖（schemadsl/cell/sqliteutil/identifier 各自独立）。未发现循环依赖。
- **耦合热点:** `repository.Store.DB()` 裸句柄是分层唯一破口（export/import 服务使用，注释护栏）；services → schema_repository 的字符串工具（`ContainsIdentifier`）是"仓储暴露非 DB 职责"的反向耦合（redesign.go:157, 259 调用）。
- **前端 store 依赖单向**: `connectionsStore → {tabsStore, toastStore}`、`settingsStore → {api, toastStore}`，无环；一处越界：connectionsStore 直写 tabsStore 内部状态（#33）。
- **事件契约**: 前后端事件名常量一一对应（constants.ts:5,8 = redesign.go:25 / transfer_service.go:30），但 payload 键名两套（connId vs targetConnId，#7 相关）。
